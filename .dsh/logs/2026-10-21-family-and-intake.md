# 2026-10-21 去掉失物登记追问；同族取值不再算矛盾

## 反馈

1. 失物登记页的「这件东西属于哪一类 / 外形更接近哪一种」没必要，删掉。
2. 点「查找可能匹配」后回答完追问，分数只有 0.2 多，怀疑没有重新估算。

## 诊断：为什么是 0.2

`score = 0.72 × CLIP 相似度 + 0.28 × 证据`。CLIP 的文本↔照片余弦**本来就在 0.2–0.35**（截图里语义 0.249），所以 0.72 那一项只有 0.18。剩下 0.28 取决于证据。

用截图里的两组指纹复算：

- 查询：杯子 / 红色 / 圆柱形 / 金属
- 候选：水瓶 / 黑色 / 圆形 / 金属

旧逻辑：材质一致（+1.0），类型、颜色、形状都判矛盾（−1.3 / −1.2 / −1.1），证据 = (1.0 − 0.8×3.6) / 3.88 ≈ **−0.49**，总分 0.72×0.249 + 0.28×0.256 ≈ **0.25**。

追问确实会重排（每次回答都会重跑 `rank_candidates`），但回答把更多字段写进指纹后，**更多的字段也参与了矛盾判定**——所以分数可能不升反降。

## 改动

1. **删掉失物登记的登记前追问**（`state/lost.py` 回退）。拾获侧保留（拿着实物的人回答成本最低），失主想补全可以去「我的记录 → 补全信息」。
2. **同族取值按一致计分**（`matching/engine.py` 的 `FAMILIES`）：
   - `cup` / `water bottle` → `drinkware`；`bag` / `backpack` → `carry`；
   - `round` / `cylindrical` / `oval` → `roundish`。
   同一组里的两个值算一致，不再互相扣分。
3. **把分数构成写到界面上**：候选排序上方一句「0.72 × 语义 + 0.28 × 证据；CLIP 原始相似度常见 0.2–0.35」，分数胶囊加了 `title` 提示。

## 效果

同一组数据复算：**0.25 → 0.394**，一致项变成「类型 / 材质 / 形状」，只剩颜色一条矛盾。

## 验证

- `pytest` 59 passed（新增同族用例；删掉两条失物追问用例）。
- 尚未在真浏览器里重跑一遍这条数据（改动是纯算法 + 文案）。

## 留下的

- 颜色、材质、标记仍然是严格比较：红色 vs 黑色就是矛盾，这不是 bug。
- 同族表是手工维护的，新增类别要记得加。
