# 404NotFound — 多模态失物招领匹配

404NotFound 是一个本地运行的 Streamlit 应用：失主用文字描述丢失的物品，拾获者上传物品照片，系统用 CLIP 做跨模态召回，用带证据校验的「物品指纹」重排候选，再通过信息增益驱动的追问逐步收敛，最后由双方确认后才交换联系方式。

> **项目定位**：黑客松 / 课程演示用的单机原型。账号、数据与模型都跑在本机，界面文案为中文，**不包含**云端部署、多租户、真实校方系统对接或移动端适配。首次使用 CLIP/BLIP 时需要下载预训练权重。

## 能做什么

- **跨模态检索**：把失物的中文/英文描述（可选照片）与拾获物品的照片映射到同一向量空间，用余弦相似度召回候选；失物有照片时使用文本+图像的混合向量。
- **证据化指纹**：从描述和图注中抽取六类属性（类型、颜色、材质、形状、品牌、特殊标记）。图注同时用**原始英文与中文译文**，因为机翻会丢细节。轻量文本模型可以补充提案，但**只有字面出现在描述或图注里的值才会被接受**；模型不可用时自动退回规则抽取。
- **主动追问**：拾获者手里有实物，所以在**检索之前**就问他 2–3 个高信息量问题（选项来自失物池的实际取值，"无特殊标记"也算答案）；失主在登记页只写描述，答案在候选排好后按信息增益追问，一次一个、最多四轮、可以跳过。失主想补全信息可以去「我的记录 → 补全信息」。
- **双向近期动态**：所有人都能看到未配对的失物与拾获，按方向/关键词/类型/地点/时间筛选；每条显示发布时间，不展示发布者身份或联系方式。登记时可以勾选是否公开到这条动态里。
- **动态重排**：每回答一次就重新排序。语义相似度与「一致/矛盾」证据线性组合；**任一边缺失的属性保持中性**，不会被当成矛盾。
- **双方确认**：一方发送配对请求，另一方在「我的物品与请求」里接受或拒绝；**接受之前任何人都看不到对方联系方式**。
- **站内通知**：登记失物时默认订阅；新拾获入库后，系统对订阅的失物重算一次证据分，超过阈值就写站内通知，顶栏显示未读数。
- **归还 / 归档**：物品可以标记为已归还/已找回或归档，记录保留；已处理的物品退出候选池、浏览页与通知匹配，也可以恢复为进行中。
- **本地留存**：报告、图片、指纹、请求与配对结果都写在本地 SQLite（`items.db`）。

## 匹配流程

1. **报失**：填写描述、最后出现地点和日期；可以选一张照片。系统生成文本向量（有照片时与图像向量归一化混合）与指纹，并把报告存入数据库。
2. **报拾获**：上传照片。配置了 `DEEPSEEK_API_KEY` 时先由 DeepSeek 视觉模型（`deepseek-flash`）识别，返回中文描述与图上文字；没配 key 或调用失败则回退本地 BLIP。系统先把从照片读到的属性列出来，**误读的点一下就剔除**；再根据未配对失物池的分歧，问 2–3 个封闭问题（外形、颜色、是否有贴纸/划痕/文字）。用户确认后提交，生成图像向量，并从「描述 + 双语图注 + 问题答案」生成指纹。
3. **召回**：只从**尚未配对**的对面类型报告里取候选，用 CLIP 语义相似度取前 8 个。
4. **重排**：逐字段比较指纹。双方都有该字段时才计入证据：一致加分、矛盾按较轻的权重扣分、缺失不计。特殊标记（划痕、贴纸、挂绳等）权重最高。
5. **追问**：若靠前候选在某个未知属性上明显分裂，就针对该属性问一个问题。问题来自固定模板，**不会把候选的具体取值当提示泄露出去**。回答会被归一化成属性并写回这件物品，对方匹配时能看到；原文不保存。
6. **确认**：对满意的候选发送请求；对方接受后写入配对表，双方才能看到彼此的联系方式，且这一对不再出现在后续候选池里。同一拾获最多 3 个待确认请求；被拒绝后 24 小时冷却，冷却到期可以重新发起；接受一个请求后，其他待确认请求会自动关闭。

> 页面上显示的分数是**排序指标，不是所有权概率**。基础分是 `0.72 × CLIP + 0.28 × 证据`；时间和地点只加软先验（同地点 +0.02、时间越近最多 +0.03），缺失或“未知/其他”不加也不扣。算法细节（权重、矛盾惩罚、翻转阈值、追问门槛）见 [`.dsh/agents/matching-engine.md`](.dsh/agents/matching-engine.md)。

登记失物时可以勾选「有新拾获时通知我」：之后每有一件拾获物品入库，系统会用它和这件失物重算一次证据分，**达到 0.40 才写一条站内通知**（阈值是启发式，不是概率）。通知只展示物品描述、照片、地点/日期与排序指标，不展示拾获者身份；联系方式仍然要双方确认。

## 页面与操作

| 页面 | 能做什么 |
| --- | --- |
| 登录 / 注册 | 账号来自 `config_auth.yaml`；注册使用自建表单，支持中文姓名、无需验证码，成功后回到登录页 |
| 首页 | 顶部导航栏切换页面；两张卡片分别进入报失 / 报拾获；下方三个计数：我的失物、我的拾获、待我确认 |
| 登记物品 | 用「我丢了东西 / 我捡到东西」切换方向：失物写描述、地点与日期，可上传一张可选照片；拾获上传 png/jpg/jpeg（≤8 MB），AI 生成描述后确认属性、回答 2–3 个封闭问题；两者都可选择是否公开到近期动态 |
| 近期动态 | 浏览所有未配对的失物与拾获；按方向、关键词、类型、地点、时间筛选；显示发布时间，不展示发布者身份或联系方式 |
| 通知 | 查看订阅失物的站内提醒；标记已读/全部已读；为某件失物重新打开候选 |
| AI 匹配 | 查看指纹、前 5 个候选（含对方属性）、一致/矛盾字段；回答追问；选择候选发送请求 |
| 我的物品与请求 | 查看进行中的失物/拾物（含属性胶囊）、已处理物品、待确认请求、已发请求、已确认配对与联系方式；每件物品能「补全信息」「处理」或「撤销登记」，已处理物品可恢复；被拒绝的请求在冷却结束后可以重新发起 |

- 注册页规则：姓名不限语言；用户名 3–20 位字母/数字/下划线/连字符；密码至少 8 位且同时包含字母和数字；邮箱需唯一。
- 导航由 `st.session_state.state` 驱动，没有 URL 路由。
- 已登录页面共用一条顶部导航栏（品牌 + 首页 / 登记物品 / 近期动态 / 通知 / 我的记录 + 退出登录），没有侧边栏；有未读通知时标签显示 `通知 · N`。样式见 `.dsh/agents/ui.md`。
- 近期动态只展示尚未配对、未处理且允许公开的失物/拾获，不展示发布者的用户名或邮箱；联系方式仍然只在双方确认后出现。
- **刷新匹配页会丢失当前会话**（问答上下文不保存），但已经确认的属性会留在物品上；需要的话去「我的记录 → 补全信息」改。

## 快速开始

### 1. 环境

- **Python 3.10 或 3.11**（推荐 3.11）。
- 不强制 GPU；CPU 可以跑，但首次加载模型与推理会明显更慢。
- 本仓库在一台 RTX 5070 + conda 环境 `aquacore` 上验证；用 venv 同样可以，命令区别只是激活方式。
- 首次使用需要联网下载 CLIP/BLIP（以及可选的 flan-t5）权重，模型缓存在用户目录，不入库；图注中译模型 `Helsinki-NLP/opus-mt-en-zh` 约 300 MB，缓存在 `models/opus-mt-en-zh/` 或 HF 缓存。
- 国内网络访问 `huggingface.co` 可能超时；启动前设置 `export HF_ENDPOINT=https://hf-mirror.com` 可走镜像。

### 2. 安装依赖

```bash
python -m venv .venv
source .venv/bin/activate            # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

版本约束以 [`requirements.txt`](requirements.txt) 为准，本文不复制版本号。

### 3. 配置账号

**最快：直接用演示账号**

```bash
python create_demo_users.py
```

会写出 `config_auth.yaml`，三个账号的密码是公开的（仅限本机演示）：

| 用户名 | 密码 | 用途 |
| --- | --- | --- |
| `alice` | `demo-pass-alice` | 失主 |
| `bob` | `demo-pass-bob` | 拾获者 |
| `demo` | `Demo`1234` | 随便试 |

每次运行都会**重新生成随机的 `cookie.key`**，所以这个文件是本机的、不要共享。已经存在时脚本会拒绝覆盖，确实要换账号加 `--force`。

**或者自己配一个**

复制模板并填写本地测试账号：

```bash
cp config_auth.example.yaml config_auth.yaml
```

`config_auth.yaml` 里必须改三处：

1. `credentials.usernames.<用户名>.password` 填 **bcrypt 哈希**，不是明文；
2. `cookie.key` 换成一个新的随机串；
3. 按需修改 `cookie.expiry_days`（默认 7 天）。

登录状态就是这个 cookie（HS256 JWT，`username` + 过期时间），所以刷新页面不会退出登录；改掉 `cookie.key` 会让已发的 cookie 立刻失效，所有人都要重新登录。

生成哈希与随机串：

```bash
python -c "import bcrypt; print(bcrypt.hashpw(b'choose-a-test-password', bcrypt.gensalt()).decode())"
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

`config_auth.yaml` 已被 `.gitignore` 排除，**不要提交真实账号、哈希或 cookie key**。

### 4. 生成样例数据（可选，会删库）

```bash
python reset_db.py
```

它**先删除 `items.db`**，再写入 4 件合成物品和 1 条配对，方便直接演示。脚本会读取 `config_auth.yaml` 创建用户，所以必须先完成第 3 步。**需要保留旧报告时不要运行。**

想复现和仓库一致的演示数据，用种子脚本（不会删库，已有物品时会拒绝运行）：

```bash
# 默认读已提交的 demo/photos/；自己的照片放 input/
HF_HUB_OFFLINE=1 python seed_demo.py
```

它默认读 `demo/photos/` 里已提交的 12 张照片（充电宝 / 水杯 / 键盘 / 鼠标 / 耳机 / 钱包 / 棒球帽 / 背包 / 围巾 / 手提包 / 行李箱 / 雨伞），把它们写成 bob 的拾获物品，并写入 alice 的对应失物描述，同时预计算 CLIP 向量与指纹。新增的 8 张来自 Open Images，来源与 CC BY 2.0 署名见 [`demo/photos/SOURCES.md`](demo/photos/SOURCES.md)。想换成自己的照片，放进 `input/`（同名文件优先用 `demo/photos/`，缺哪张去哪张）。

### 5. 下载模型（新机器/协作者只需一次）

模型权重不放进 git（体积大、更新频繁）。新环境先跑一次：

```bash
python download_models.py
```

脚本默认使用 `hf-mirror.com`，会拉取 BLIP、CLIP、flan-t5 与中译模型；已缓存的会跳过，可重复运行。

### 6. 启动

模型就绪后，先激活环境，再用 `run.sh` 启动（自动设置 `HF_HUB_OFFLINE=1`）：

```bash
conda activate aquacore   # 或 source .venv/bin/activate
./run.sh
```

`run.sh` 只负责设置离线变量并调用 `streamlit`；它不会替你激活环境，提示找不到 `streamlit` 时先检查这一行。

也可以手动启动。首次启动（需要下载模型时）走镜像：

```bash
export HF_ENDPOINT=https://hf-mirror.com
streamlit run app.py
```

模型缓存到 `~/.cache/huggingface` 后，改用离线模式启动，避免每次加载都向不可达的 `huggingface.co` 发请求：

```bash
export HF_HUB_OFFLINE=1
streamlit run app.py
```

打开 `http://localhost:8501`。端口被占用时用 `streamlit run app.py --server.port 8502`。

**必须从仓库根目录启动**：`items.db` 与 `rooms.json` 都按当前工作目录解析，换目录会用到另一个空库或直接找不到地点文件。

### 7. 走一遍完整流程

1. 用账号 A 报一件失物（例如「黑色耳机，充电盒有红色贴纸」）。
2. 用账号 B 报一件拾获物品并上传照片。
3. 在 A 的匹配页回答一两个追问，观察候选顺序变化。
4. A 对 B 的物品发送请求；登录 B，在「我的物品与请求」里接受。
5. 双方在「已确认的匹配」中看到对方联系方式。

## 可选：接入 DeepSeek 视觉模型

不配置也能跑，走本地 BLIP；配置后拾获登记会用视觉模型识图，能读出型号、序列号这类图注写不出的细节。

**需要手工填的东西统一放在仓库根目录的 `settings.yaml`**（已 gitignore，不会提交）：

```bash
cp settings.example.yaml settings.yaml
```

```yaml
deepseek:
  enabled: true
  api_key: ""                      # 填 sk-... 才启用；留空则整个功能关闭
  model: deepseek-flash
  url: https://api.deepseek.com/chat/completions
  timeout: 25                      # 秒，超时回退本地 BLIP

fingerprint:
  text_model: google/flan-t5-small  # off = 只用规则抽取
```

- 环境变量优先级更高，临时改不用动文件：`DEEPSEEK_API_KEY`、`DEEPSEEK_VISION`、`DEEPSEEK_VISION_MODEL`、`DEEPSEEK_API_URL`、`DEEPSEEK_TIMEOUT`、`FINGERPRINT_TEXT_MODEL`。
- `settings.yaml` 只在进程启动时读一次：改完要重启 `./run.sh`。
- 只在**登记时**调用一次，结果随指纹入库；检索、重排、追问全部仍在本机。
- 失败、超时、没有 key 都只是回退 BLIP，不会让登记失败。
- **隐私**：开启后照片会发送到 DeepSeek API；不想让照片离开本机就别填 key。页面上的隐私说明会随开关变化。
- 实现只用标准库 `urllib`，不引入 openai SDK。

## 配置项

| 配置 | 作用 | 默认 / 说明 |
| --- | --- | --- |
| `FINGERPRINT_TEXT_MODEL` | 指纹抽取用的文本生成模型 | `google/flan-t5-small`；设为 `off` 可跳过，只用规则抽取 |
| `config_auth.yaml` | 账号、cookie、有效期 | 不入库；缺失时应用直接停止并提示 |
| `items.db` | SQLite 数据库 | 相对**启动目录**；被 `.gitignore` 排除 |
| `rooms.json` | 地点下拉选项 | 想增删地点直接改这个文件 |

离线或模型下载失败时的降级行为：没有 flan-t5 → 规则抽取照常；没有 BLIP → 提示手填描述；没有 CLIP → 无法生成/比较向量，报告会报错停止。详见 [`.dsh/agents/operations.md`](.dsh/agents/operations.md)。

## 数据、隐私与边界

- **联系方式门禁**：只有状态为 `accepted` 的配对才会 JOIN `users` 表返回用户名与邮箱；未确认请求只显示物品描述。
- **请求权限**：只能对自己发布的报告发起请求；只有对方能接受或拒绝。
- **图片清洗**：入库前统一做 EXIF 方向纠正、缩放到最长边 1600、转 RGB，**不保留 EXIF**（包括定位信息）；上传上限 8 MB，像素上限 2000 万。
- **追问上下文不落库**：只保存归一化后的属性值，不保存回答原话与问答历史。
- **通知只给订阅者**：通知只 JOIN `items`，展示描述、照片、地点/日期与排序指标，不含拾获者用户名或邮箱；不发邮件、短信或推送。
- **归还/归档保留记录**：`item_status` 只存状态、操作者、时间与本人备注；备注不进入候选、浏览页或通知。它与「撤销」不同：撤销是硬删除，状态可以恢复。
- **近期动态默认公开**：失物与拾获的描述、照片、地点/日期、发布时间与已共享属性对所有已登录用户可见；登记时可以取消公开。页面提示不要写门牌号、证件号等敏感信息；联系方式仍然需要双方确认。
- **发布时间与内容指纹**：每个帖子底部显示「首次发布于：… · 内容指纹 …」；`report_meta.published_at` 只用来标明先后，`items.time` 是丢失/拾获日期，两者分开显示。
- **查重与水印**：上传图片时用 64-bit dHash 比对已有帖子（Hamming ≤ 6 提示），提交描述时做文本近似检查；公开/列表图片加底部水印（帖子尾号 + 日期）。两者都只提示，不阻断提交。浏览器截图/保存无法真正禁止。
- **本地信任边界**：`items.db` 用 Python pickle 存图片数组与向量，只应作为可信本地数据使用，不要当交换格式。
- **不入库的内容**：`items.db`、`config_auth.yaml`、`settings.yaml`、`input/` 私人照片与模型权重；原因写在 [`.gitignore`](.gitignore) 里。演示照片在 [`demo/photos/`](demo/photos/)，是提交进仓库的。

## 测试与校验

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

## 已知限制

- **时间/地点只作为软先验**：同地点 +0.02、时间接近最多 +0.03，缺失或“未知/其他”不参与；不是硬过滤。权重（0.03/0.02/14 天）未用真实数据校准。
- **撤销登记不可恢复**：会连带删除该物品的指纹与相关待确认请求；已经有双方确认配对的物品不允许撤销。
- **拒绝有 24 小时冷却**：冷却到期可以重新发起；同一拾获最多 3 个待确认请求，接受一个后其他待确认会自动关闭。
- **待处理请求不会把物品移出候选池**：有意为之，避免一个（可能是冒领的）请求阻塞其他人；用上限 3 控制骚扰。
- **图注是机器翻译**：BLIP 先出英文，再由 `opus-mt-en-zh` 翻成中文，可能出现「close up → 关闭」这类误译；提交前可以手动修改，模型本身不保证准确。
- 没有速率限制、邮箱验证、封禁或审计日志；适合演示，不适合直接对外服务。
- 近期动态会一次性加载全部未配对失物/拾获（含拾获图片 BLOB）；报告数量很大时会变慢，当前没有分页（见 `backlog.md`）。
- **公开失物描述可能被照抄**：现在会在上传/提交时做图片 dHash 与文本近似提示，但不阻断；发布时间与内容指纹只是先后标记，不是所有权证明。
- **截图/保存无法禁止**：水印只能让复制品带帖子尾号与日期；被裁剪的图无法追溯。没有一次性交接码/线下核验。
- 失物照片是**可选**的；没有照片时仍只用文本向量。混合权重 0.5/0.5 是起点，未用真实数据校准。
- 失物照片和拾获照片可能是同一张（比如从动态里保存的）；dHash 会在上传时提示近似重复，但不会阻止提交，本质上仍是“照抄描述”的同类风险。
- 公开/不公开只能在登记时设置，事后没有单独开关。
- **通知只在站内**：没有邮件、短信或推送，也不会在已有拾获上回溯触发；阈值 0.40 来自演示数据，未用真实数据校准。
- **订阅按单件失物**：没有「关键词/类型/地点」的保存搜索；订阅在拾获登记时同步计算，订阅很多时会拖慢登记。
- **归还是单方标记**：没有双方交接确认；也没有自动归档/保留期。首页统计仍按「已登记」总数计算，只有「我的记录」区分进行中/已处理。
- 单进程 SQLite，没有迁移脚本；多会话并发写入的锁行为尚未实测。
- 仓库只有单元测试与 mock 烟测；真实端到端与演示数据的离线评估已记录在 `.dsh/logs/`，但没有真实用户规模的数据。
- `evaluate.py` 默认只有 12 对合成演示样本（12 条失物描述都来自照片而非真实用户口吻），且只评估“失物 → 拾获”方向；真实效果需要更多标注对。
- 排名分不是所有权概率；生成属性也需要人工复核。
- **Streamlit 自带控件的文案改不了**：文件上传的 `Upload`、日期选择器的月份与星期仍是英文，只能靠自定义组件解决。
- **主题只在启动时生效**：改 `.streamlit/config.toml` 后必须重启 `streamlit run`，浏览器刷新不够。

当前卡点与下一步要找谁，见 [`backlog.md`](backlog.md)。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| `缺少 config_auth.yaml` | 复制 [`config_auth.example.yaml`](config_auth.example.yaml) 并填写哈希与 cookie key |
| `No module named 'streamlit'` | venv 未激活或依赖未装：重新 `pip install -r requirements.txt` |
| `numpy.core._multiarray_umath` 导入失败 | 系统 Python 与 venv 的 numpy 混装或损坏：删掉 `.venv` 重建，不要装进系统环境 |
| 图片图注提示不可用 | BLIP 权重未下载或网络不可用：设置 `HF_ENDPOINT=https://hf-mirror.com` 后重启，或手填描述继续 |
| 图注仍是英文 | 中译模型 `models/opus-mt-en-zh` 缺失且无法下载；补模型或手动改描述 |
| 图片描述一直转圈 / 很慢 | 首次在下载 BLIP（约 1 GB）；若缓存已完整仍慢，是加载时在向 `huggingface.co` 发 HEAD。设 `HF_ENDPOINT` 下载，之后用 `HF_HUB_OFFLINE=1` 启动 |
| 候选列表为空 | 对面还没有未配对的报告：换账号先报一件，或运行 `reset_db.py` |
| 数据「消失」 | 从别的目录启动了应用，或运行过 `reset_db.py`（会删库） |
| 配色 / 圆角没生效 | `.streamlit/config.toml` 只在进程启动时读取：重启 `streamlit run` |
| 刷新页面后要求重新登录 | cookie 过期（`cookie.expiry_days`）、换过 `cookie.key`，或浏览器禁用了 cookie；重新登录即可，登录状态默认保持 7 天 |

更多排查见 [`.dsh/agents/operations.md`](.dsh/agents/operations.md)。

- 本次改动的详细说明、验证结果与后续建议见 [`MODIFICATIONS.md`](MODIFICATIONS.md)。

开发在 `dsh` 分支进行，`main` 只在用户明确确认后合并。提交前先确认分支：

```bash
[ "$(git branch --show-current)" = dsh ] || { echo "wrong branch, aborting"; exit 1; }
```

**为什么 README 不是智能体的入口**：DSH 只自动加载命名为 `AGENTS.md` / `CLAUDE.md` 的指令文件，`README.md` 不会被注入上下文。所以给人看的内容留在这里，给智能体的索引放在根目录的 `AGENTS.md`。
