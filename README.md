# 404NotFound - Multimodal Lost and Found

404NotFound is a Streamlit application for recording lost and found items and suggesting possible matches between them. It combines image embeddings and text embeddings in a shared semantic space so that an item can be found even when two reports use different descriptions.

## Features

- Account registration, login, logout, and personal item lists.
- Lost-item reports with a text description, location, and date.
- Found-item reports with an image, an automatically generated description, location, and date.
- Similarity-based suggestions between lost-item descriptions and found-item images.
- Review screens for accepting or rejecting a suggested match.
- Local SQLite storage for reports, users, and match records.

## Matching workflow

1. A found-item image is encoded with **clip-ViT-B-32**. The image can also be described using the **Salesforce/blip-image-captioning-base** captioning model.
2. A lost-item description is encoded with **clip-ViT-B-32-multilingual-v1**.
3. The application compares embeddings using semantic similarity and presents the highest-scoring candidate when its score exceeds the current threshold (**0.25**).
4. Users review the proposed match in the application. A confirmed suggestion is recorded in SQLite.

Locations and dates are collected with each report. The current candidate search is based on embeddings; it does not enforce a location or date filter. Notifications are displayed within the application rather than delivered by push message.

## Installation

Python 3.10 or newer is required. Create a virtual environment and install the dependencies:

~~~bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
~~~

Create a local authentication configuration from the template:

~~~bash
# Linux/macOS:
cp config_auth.example.yaml config_auth.yaml
# Windows PowerShell:
# Copy-Item config_auth.example.yaml config_auth.yaml
~~~

Edit **config_auth.yaml**: replace the example user's email, display name, and password hash with values for a local account, and replace the cookie key with a new random secret. Passwords must be stored as bcrypt hashes, not plaintext. For example:

~~~bash
python -c "import bcrypt; print(bcrypt.hashpw(b'change-this-password', bcrypt.gensalt()).decode())"
python -c "import secrets; print(secrets.token_urlsafe(32))"
~~~

The first command prints an example bcrypt hash. Use your own password rather than the literal example above. The second command generates a cookie secret.

To initialize the local database with example entries:

~~~bash
python reset_db.py
~~~

**Warning:** reset_db.py deletes any existing **items.db** and recreates it. Do not run it against a database containing reports you need to keep.

Start the application:

~~~bash
streamlit run app.py
~~~

By default, Streamlit serves the app at http://localhost:8501. The first image or text inference may take time while model weights download.

## Usage

**Report a lost item:** Sign in, choose the lost-item option, enter a description, select the last-known location and date, and search for a match.

**Report a found item:** Sign in, choose the found-item option, upload a picture, review its generated description, select a location and date, and submit the report.

**Review reports:** Open the profile to see existing reports and match status. A match suggestion can be accepted or declined on its review screen.

## Data handling and limitations

The local **config_auth.yaml** contains account configuration, while **items.db** contains account details and report data, including uploaded item images. Both files are excluded from Git. Avoid committing real user reports, credentials, or captured images. The example images generated by the database reset utility do not contain personal data.

The app is a local prototype, not a production identity-verification or ownership-verification service. A user can see another report's contact information after accepting a suggested match; use test accounts when evaluating the app. Database image data and embeddings are currently serialized with Python pickle and must not be read from an untrusted database.
